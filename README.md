# Nexa Backlink: بک‌لینک‌سازی چندسایته و چنداکانته با هوش مصنوعی

اکانت‌هایت را (تکی یا گروهی، صدتا صدتا) به سیستم می‌دهی، سایت‌هایت را تعریف می‌کنی و برای هر
سایت یک یا چند **کمپین** با زمان‌بندی دلخواه می‌سازی. از آن به بعد سیستم خودش در بازه‌هایی که
تعیین کرده‌ای با هوش مصنوعی محتوا می‌نویسد. این محتوا مقاله‌ی بک‌لینک یا پست سوشیال است و
بین اکانت‌ها می‌چرخد. بعد آن را منتشر می‌کند و بعداً برمی‌گردد و چک می‌کند لینک زنده و dofollow هست یا نه.

موتور انتشار (adapterهای پلتفرم‌ها، تولید محتوا، بررسی لینک) از ریپوی
[backlink](https://github.com/aminjn/backlink) آمده است. این پروژه آن را **چندسایته و چنداکانته**
کرده و همه‌چیز را از داشبورد قابل مدیریت کرده است، بدون فایل YAML.

```
هر ۶۰ ثانیه
 └─ کمپین‌هایی که وقتشان رسیده (و داخل روز/ساعت/تاریخِ فعالشان هستند)
     ├─ سقف روزانه/کل کمپین پر نشده؟
     ├─ انتخاب نوع محتوا (مقاله یا سوشیال، به نسبتی که گفته‌ای)
     ├─ انتخاب اکانت: کم‌استفاده‌ترین اکانتی که cooldown و سقف روزانه‌اش اجازه می‌دهد
     ├─ تولید محتوا با هوش مصنوعی (یک لینک طبیعی + انکرتکست متنوع + صفحات عمقی)
     ├─ انتشار با API رسمی همان پلتفرم → ثبت
     └─ زمان اجرای بعدی = الان + عدد تصادفی بین «حداقل» و «حداکثر» فاصله
هر ۱۲ ساعت: بررسی بک‌لینک‌ها (زنده؟ dofollow؟)
اکانتی که ۳ بار پشت‌سرهم خطا بدهد خودکار متوقف می‌شود تا بقیه کار کنند.
```

## مفاهیم

| | توضیح |
|---|---|
| **سایت** | سایتی که باید لینک بگیرد: آدرس، زبان، حوزه، توضیح، کلمات کلیدی، انکرها، صفحات عمقی. هر تعداد سایت که بخواهی. |
| **اکانت** | یک حساب روی یک پلتفرم (تلگرام، بلواسکای، وردپرس، Dev.to، ...). اطلاعات ورود **رمزنگاری‌شده** ذخیره می‌شود. هر اکانت «گروه»، حداقل فاصله بین دو پست و سقف روزانه‌ی خودش را دارد. |
| **کمپین** | «برای سایت X، با این اکانت‌ها (گروه/پلتفرم/انتخاب دستی)، هر ۹۰ تا ۲۴۰ دقیقه، از ساعت ۸ تا ۲۳، شنبه تا چهارشنبه، از تاریخ A تا B، حداکثر ۶ تا در روز» |

یک اکانت می‌تواند در چند کمپین (برای چند سایت) استفاده شود. سقف روزانه‌ی اکانت روی همه‌ی کمپین‌ها با هم اعمال می‌شود.

## پلتفرم‌ها

| بک‌لینک (مقاله) | سوشیال |
|---|---|
| Telegraph (بدون حساب) · WordPress · Blogger · Dev.to · Hashnode · Tumblr · Medium · Ghost · Write.as | Telegram · X · LinkedIn · Facebook Page · Instagram · Threads · Mastodon · Bluesky · Reddit · Pinterest · Webhook (n8n/Make/Zapier/Buffer → هر جای دیگر) |

همه از **API رسمی** کار می‌کنند. برای هر اکانت، توکن یا کلید API همان اکانت را وارد کن. لیست
فیلدهای هر پلتفرم را در فرم «افزودن اکانت» یا از `GET /api/kinds` ببین.
ورود با یوزر/پسورد از طریق مرورگر، دورزدن کپچا، اسپم کامنت/فروم و ساخت انبوه اکانت فیک در این
سیستم **نیست و اضافه نمی‌شود**. پلتفرم‌ها این کارها را تشخیص می‌دهند و اکانت را می‌بندند، و گوگل
هم بابت link scheme به سایت پنالتی می‌دهد. برای پلتفرمی که اینجا نیست، یک کلاس کوچک در
`app/publishers/` اضافه کن (README ریپوی backlink را ببین) یا از Webhook و n8n استفاده کن.

## نصب روی سرور خام (آروان یا هر Ubuntu 22.04/24.04)

```bash
ssh ubuntu@<IP-سرور>
sudo apt-get update && sudo apt-get install -y git
git clone -b claude/cool-gates-uz854n https://github.com/aminjn/nexacomercial && cd nexacomercial
sudo bash deploy/install.sh
```
اسکریپت این کارها را انجام می‌دهد:
- Docker را از مخزن Ubuntu نصب می‌کند، چون سایت Docker آی‌پی ایران را بسته است.
- میرور رجیستری آروان را تنظیم می‌کند.
- فایل `.env` را با رمز داشبورد و کلید رمزنگاری تصادفی می‌سازد.
- برنامه و **Ollama** را بالا می‌آورد و مدل `qwen2.5:7b` را دانلود می‌کند.

آخر کار آدرس داشبورد و رمز را چاپ می‌کند. رمز در فایل `.env` هم ذخیره می‌شود.

| متغیر اسکریپت | پیش‌فرض | توضیح |
|---|---|---|
| `OLLAMA_MODEL` | `qwen2.5:7b` | مدلی که دانلود می‌شود. `OLLAMA_MODEL= ` (خالی) یعنی Ollama نصب نشود و از API بیرونی استفاده شود |
| `REGISTRY_MIRROR` | `https://docker.arvancloud.ir` | میرور Docker Hub |
| `PIP_INDEX_URL` | pypi.org | اگر PyPI کند یا بسته بود، یک میرور بده |

مثال: `sudo OLLAMA_MODEL=qwen2.5:14b bash deploy/install.sh`

### سرور مناسب برای Ollama (بدون GPU، روی CPU)
| مدل | رم لازم | پیشنهاد سرور | کیفیت فارسی |
|---|---|---|---|
| `qwen2.5:3b` | ~۴ گیگ | ۴ هسته / ۸ گیگ | قابل قبول برای پست کوتاه |
| `qwen2.5:7b` (پیش‌فرض) | ~۸ گیگ | ۸ هسته / ۱۶ گیگ | خوب |
| `qwen2.5:14b` | ~۱۶ گیگ | ۸–۱۶ هسته / ۳۲ گیگ | بهتر، ولی کندتر |

روی CPU نوشتن هر مقاله چند دقیقه طول می‌کشد. چون انتشارها با فاصله‌ی چندساعته‌اند، این مشکلی
ایجاد نمی‌کند. حداقل ۴۰ گیگ دیسک بگیر. مدل را بعداً هم می‌توانی عوض کنی:
```bash
docker compose exec ollama ollama pull gemma3:12b     # دانلود مدل جدید
nano .env                                             # APP_LLM_MODEL=gemma3:12b
docker compose --profile ollama up -d
```

### بعد از نصب
- پورت `8020` را در فایروال آروان باز کن. بهتر است فقط برای آی‌پی خودت باز باشد.
- پورت Ollama (11434) بیرون باز نیست و فقط خود برنامه به آن دسترسی دارد.
- بکاپ: پوشه‌ی `data/` و فایل `.env`.
- آپدیت: `git pull && docker compose --profile ollama up -d --build`
- لاگ: `docker compose logs -f nexa`

### به‌جای Ollama: API بیرونی
هر سرویس OpenAI-compatible (OpenRouter، سرویس‌های واسط ایرانی و ...) با سه متغیر کار می‌کند:
`APP_LLM_BASE_URL`، `APP_LLM_API_KEY` و `APP_LLM_MODEL`. برای Claude هم از
`APP_LLM_PROVIDER=anthropic` استفاده کن.

> ⚠️ `APP_SECRET_KEY` در `.env` اطلاعات اکانت‌ها را رمز می‌کند. اگر گم شود، اکانت‌ها قابل بازخوانی نیستند.

## گردش کار

1. **سایت‌ها** → سایت‌ها را تکی اضافه کن یا CSV بده (`examples/sites.csv`).
2. **اکانت‌ها** → تکی از فرم، یا گروهی با CSV/JSON (`examples/accounts.csv`). هر اکانت را با دکمه‌ی «تست» یک‌بار امتحان کن.
3. **کمپین‌ها** → سایت، اکانت‌ها (مثلاً گروه `shop`)، بازه‌ی زمانی، ساعت و روزهای فعال و سقف‌ها را تعیین کن.
   «پیش‌نمایش» محتوا را بدون انتشار می‌سازد.
4. در `.env` اول `APP_DRY_RUN=true` بگذار، خروجی را در «انتشارها» ببین، بعد `false` کن.

### فرمت ورود گروهی اکانت‌ها
ستون‌های `label, kind, tag, min_hours_between, daily_limit, notes` تنظیمات اکانت‌اند و **هر ستون
دیگری اطلاعات ورود** آن پلتفرم است. در یک فایل می‌توان پلتفرم‌های مختلف داشت:

```csv
label,kind,tag,min_hours_between,daily_limit,bot_token,chat_id,handle,app_password
tg-1,telegram,shop,6,4,123456:ABC...,@channel1,,
bsky-1,bluesky,shop,8,3,,,me.bsky.social,xxxx-xxxx-xxxx-xxxx
```
یا به شکل JSON: `[{"label":"b1","kind":"bluesky","tag":"shop","creds":{"handle":"...","app_password":"..."}}]`

ردیف‌هایی که پلتفرمشان ناشناخته است یا فیلد الزامی ندارند رد می‌شوند و خطایشان نمایش داده می‌شود.

## CLI و API
```bash
docker compose exec nexa python -m app.cli import-accounts accounts.csv --tag shop
docker compose exec nexa python -m app.cli import-sites sites.csv
docker compose exec nexa python -m app.cli run <campaign_id> --dry-run
docker compose exec nexa python -m app.cli test <account_id> [--site 1]
docker compose exec nexa python -m app.cli tick | verify | list | kinds
```
API (با همان Basic Auth): `GET /api/sites|accounts|campaigns|publications|kinds`،
`POST /api/accounts/import?tag=` و `POST /api/sites/import` (بدنه = متن CSV یا JSON).

## تنظیمات `.env`
| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `APP_TICK_SECONDS` | 60 | هر چند ثانیه کمپین‌های سررسیده بررسی شوند |
| `APP_MAX_JOBS_PER_TICK` | 5 | حداکثر انتشار در هر تیک (جلوگیری از انفجار انتشار) |
| `APP_ACCOUNT_MAX_FAILURES` | 3 | توقف خودکار اکانت بعد از چند خطای پیاپی |
| `APP_TIMEZONE` | Asia/Tehran | ساعت‌ها و روزهای کمپین به این منطقه‌ی زمانی هستند |
| `APP_DRY_RUN` | false | تولید بدون انتشار |

## نکته‌ی سئو
لینک‌سازی انبوه و ماشینی از نظر گوگل «link scheme» است. با چند سایت و اکانت زیاد، وسوسه‌ی بالا بردن
حجم زیاد است. سقف‌ها را پایین نگه دار (مثلاً ۱–۲ مقاله در روز برای هر سایت)، روی پلتفرم‌هایی منتشر
کن که خودت در آن‌ها حساب واقعی و مخاطب داری، و قوانین هر پلتفرم را رعایت کن (مثلاً در Reddit فقط
در ساب‌ردیت خودت یا جایی که لینک مجاز است). این‌طوری هم اکانت‌ها سالم می‌مانند و هم سایت.
